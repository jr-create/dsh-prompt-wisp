fix: compact mode now races models too - a no-op rewrite reads as broken

Live feedback: the local rules pass only fired on dictionary hits, so
real drafts came back unchanged and the compact mode read as broken.
The user switched to detail mode to get any real optimization.

Both modes now go through the model race; they differ in budget and
prompt face, not in engine:

- compact: lean system prompt (5 lines, tuned for short output), no
  context read, 6s per-route budget. Measured 0.5-1.5s per call.
- detail: full structured prompt, session context grounding, 10s
  per-route budget. Measured 1.4-4s.

The local rules engine is demoted to the instant fallback when the race
fails or times out - a rule-passed draft in the same second beats a
provider error, and trim-filler still applies there.

composeSystemPrompt now owns both faces: the compact face lives in
config.js as a config concern (the engine keeps the base prompt).

68 offline tests (was 67): the compact race face, the instant local
fallback, and the detail fallback behavior.
