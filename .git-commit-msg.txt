feat: dual-engine optimization - local compact (9-50ms), raced detail (3-6s)

User targets: compact within 1-2s, detailed within 10s. A remote model
call cannot do 1-2s, so the engines split:

- COMPACT (简便优化, default) now runs a local rules engine
  (lib/local.js): a 去废话 dictionary (stacked interjections, trailing
  gratitude, mid-sentence softeners, vague hedges like 随便/大概),
  shape normalization, and adjacent-duplicate-sentence folding - all
  line-structure preserving, never returning empty, meaning preserved
  by construction. Zero model calls, zero token cost. Measured 9-50ms
  per request on the live route (5-run avg 18ms), budget 2s.
- DETAILED (详细优化) races up to three model routes (primary +
  other registered providers' first models) and takes the first clean
  answer; 10s per-route budget. Measured 3.2-5.6s on the live route.
  Context grounding and the config-composed system prompt still apply.

The settings page copy documents both engines; trim-filler applies to
both. The single-route optimizePrompt stays exported for callers that
want the classic behavior with its self-healing fallbacks.

67 offline tests (was 58): local rules (meaning preservation, no-empty
invariant, 20k-char speed budget), race resolution, and the compact/
detail dispatch through /optimize.
